# slides-extractor — memory

## Что это
CLI-утилиты для обучающих видео, где «видео» — это смена статичных слайдов
(скринкаст/презентация в стиле Gemini Notebook: акварельные иллюстрации +
текстовые таблицы/подписи поверх). Два независимых инструмента:

1. `extract_slides.py` — режет видео на слайды + точные тайминги, умеет
   пересобрать видео из обновлённых слайдов с теми же интервалами.
2. `slide_processor.py` — пакетно переверстывает сами слайды через
   Gemini Vision + Imagen 3 + Pillow (убирает визуальный мусор/водяные знаки,
   генерирует чистый фон, накладывает обратно оригинальный текст).

Скрипты **не связаны напрямую** — соединяются через файловую конвенцию имён
(`NN.png` / `NN_upd.*`) и вспомогательный `move_upd_files.sh`.

## Стек / зависимости
- Python 3.10+ (extract_slides.py) / 3.11+ (slide_processor.py)
- `requirements.txt`: opencv-python-headless, numpy (extract) +
  google-genai, pillow, pydantic, python-dotenv, tenacity, rich (processor)
- `ffmpeg`/`ffprobe` в PATH — нужен только для `extract_slides.py --update`
- `.env` (не в git, см. `.env.example`) — `GEMINI_API_KEY`, `VISION_MODEL`
  (по умолчанию `gemini-2.5-flash`), `IMAGEN_MODEL`
  (по умолчанию `imagen-3.0-generate-002`), `FONT_TITLE_PATH`, `FONT_BODY_PATH`
- Шрифты (`Inter-Bold.ttf`, `Inter-Regular.ttf`) — не в репо, кладутся вручную
  в `assets/fonts/` (см. `assets/fonts/README.md`), нужны для кириллицы

## Карта файлов
| Путь | Назначение |
|---|---|
| `extract_slides.py` | извлечение слайдов из видео + `--update` пересборка |
| `slide_processor.py` | AI-регенерация слайдов (Gemini Vision → Imagen 3 → Pillow) |
| `move_upd_files.sh` | переносит `*_upd.*` файлы из папки слайдов в `<stem>_upd/` |
| `tz.md` | полное ТЗ на `slide_processor.py` (источник истины по алгоритму/схеме) |
| `.env.example` | шаблон конфига (реальный `.env` — секрет, не коммитить) |
| `assets/fonts/` | сюда класть реальные .ttf (не входят в репо) |
| `videos/` | локальные данные, в `.gitignore`, не коммитится |

## Как связаны два скрипта (важно, не очевидно из кода)
`slide_processor.py` пишет `NN_upd.jpg` **рядом с оригиналом** внутри
`videos/<video>/` (а не в отдельную папку!), потому что так явно требует
`tz.md`. Чтобы `extract_slides.py --update` увидел эти файлы, их нужно
сначала перенести в сестринскую папку `<stem>_upd/` — для этого и существует
`move_upd_files.sh`. Полная цепочка:

```
extract_slides.py videos/                  # 1. нарезать слайды
python slide_processor.py --input-dir videos   # 2. NN.png -> NN_upd.jpg рядом
./move_upd_files.sh videos                 # 3. перенести *_upd.jpg в <stem>_upd/
extract_slides.py videos/ --update         # 4. пересобрать видео с новыми слайдами
```

## Архитектура slide_processor.py (нетривиальные решения)
- Imagen 3 (`imagen-3.0-generate-002`) — **только text-to-image**, нет
  image-to-image/inpainting. Поэтому Gemini Vision не редактирует картинку,
  а генерирует `imagen_prompt` (текстовое описание стиля/композиции без
  текста), и уже по нему Imagen рисует фон с нуля. Итоговая раскладка объектов
  на фоне не пиксель-в-пиксель совпадает с оригиналом — это осознанный
  компромисс (подтверждено пользователем).
- Раскладка текста Pillow — **упрощённая** (`TextBlock`: title + description +
  x/y/max_width), без попытки воспроизводить таблицы с заливкой ячеек как в
  оригинале (подтверждено пользователем: "упрощённо, текстовые блоки").
- `main_title` в pydantic-схеме не имеет координат — в коде захардкожен
  top-left (0.05, 0.04) как условный заголовок слайда. Если не понравится —
  править в `render_slide()`.
- Halo/подложка под текст — не блюр, а `stroke_width`+`stroke_fill` (простой
  и надёжный способ читаемости текста на сложном акварельном фоне).
- Вывод всегда `.jpg` (JPEG q=95, 1920×1080) независимо от расширения
  исходника — так буквально написано в ТЗ (`<имя>_upd.jpg`), даже для `.png`.
- Идемпотентность: пропускает файл, если `NN_upd.jpg` уже существует, кроме
  `--force`. Retry на 429/5xx через tenacity (exp backoff), до 3 проходов
  сверки (reconciliation loop) для файлов с ошибками.
